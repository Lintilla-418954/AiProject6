Presentation

Vim Station

A browser-based Vim puzzle game that teaches command fluency by repairing corrupted robot programs.

Project goal

Turn a starting buffer into a target buffer using valid Vim keystrokes while a robot in the scene performs the result.

Core idea

Players solve programming puzzles with real keystrokes, not mouse-driven editing.

What it is

Function of the project

Vim Station is a desktop-browser puzzle game designed to teach Vim from first movement through advanced commands.

Gameplay loop

  • A puzzle starts with a corrupted robot program.
  • The player edits the text buffer using Vim-like commands.
  • Each accepted keystroke updates the program and robot behavior.
  • The player must match the target buffer before the keystroke budget expires.

Why it matters

  • It teaches keyboard-first editing.
  • It turns abstract Vim commands into visual puzzle feedback.
  • It gives immediate, concrete rewards for correct editing.

The repository specification describes it as “a web-based puzzle game that teaches vim from zero to advanced by having players solve puzzles using only vim keystrokes.”

User experience

How players interact with it

Gameplay is desktop-first and keyboard-driven. Players do not use the mouse for buffer edits; they use Vim commands such as motion, deletion, insertion, and change operations.

Typical actions

  • h j k l to move the cursor
  • w / b / $ for motions
  • dd / D / c / dw for edits
  • i, a, o to insert or open lines

Game feedback

  • Target text is checked after each accepted token.
  • The robot scene visually reacts to the edited program.
  • Hints and budgets reinforce efficient play.
Start:  move to word  ->  delete word  ->  insert corrected text

Game design and curriculum

The project organizes learning into a curriculum of ordered Vim concepts, each built into puzzles and chapters.

Concept Commands example
Navigationh j k l, w b e

Chapters unlock as the player passes earlier stages, with test-out puzzles verifying mastery of the chapter’s commands.

Key system

Core engine: Vim semantics

The heart of the project is a deterministic, serializable editor engine that models Normal mode, counts, pending commands, ranges, and cursor movement.

Public API

initialState(lines, cursor)
step(state, token)
run(state, tokens)
parseKeys(notation)
formatKeys(tokens)

Important behaviors

  • Count handling is preserved during operator parsing.
  • Cursor destinations are separated from operator ranges.
  • Multi-key motions and half-open ranges follow Vim semantics.
  • Commands like dw, cw, %, and J are modeled carefully.

This is critical because the project must stay aligned with real Neovim behavior and produce trustworthy puzzle feedback.

Movement

Editing

dw deletes the current word, while cw changes the word and enters insert mode, preserving the new cursor semantics.

Quality and validation

Testing, oracle checks, and correctness

The repository includes strong verification scripts, including content validation and example verification. These are important because a Vim-based game only succeeds if the engine reproduces the editor’s actual behavior faithfully.

  • npm test runs unit and engine regression tests.
  • npm run typecheck validates TypeScript correctness.
  • npm run validate:content checks puzzle integrity.
  • npm run verify:examples confirms example semantics.
  • npm run verify:oracle compares behavior against Neovim-backed oracle checks.

This approach is especially useful in a project where small parsing bugs can cause large gameplay and pedagogy problems.

Conclusion

Summary

Vim Station combines a browser game, a curriculum, and a Vim engine into a single educational product. It teaches editing by making the player solve real robot-program repair challenges using only keyboard-based commands.

What makes it strong

  • Clear teaching arc through chapters and concepts
  • Immediate feedback from scene and buffer changes
  • Real Vim semantics rather than simplified fiction
  • Rigorous testing and oracle validation

What it teaches

  • Cursor motion and line navigation
  • Deletion, change, and word operations
  • Counts, multi-key motions, and range semantics
  • Efficient editing habits in a real developer workflow

In short: this project turns Vim from a memorization exercise into a playable, interactive, measurable skill-building experience.
